Em 2026-09-28 o usuário pediu (ainda não iniciado — pediu pra "guardar" o briefing antes de começar) um novo `/site` dentro do [[project_deliveryhub]]: uma página de apresentação institucional/comercial do produto DeliveryHub, separada do app em si (não é o painel do restaurante nem a loja do cliente — é a vitrine que vende a plataforma).

**Estrutura de páginas pedida:**
- Home geral — resumo de tudo, tom apelativo (chamativo/persuasivo) pra quem não conhece o produto ainda, com CTA de cadastro.
- "Quem somos".
- Página para **estabelecimentos** — foco em vantagens de se cadastrar: economia, ganhos, benefícios do negócio.
- Página para **usuários finais** — foco em poder comprar de estabelecimentos próximos e ver tudo que está sendo vendido ao redor deles.
- Página para **entregadores** — como ganham dinheiro, benefícios de fazer entregas no próprio bairro.
- Botão/CTA "Cadastre-se" presente.

**Diretriz de design (explícita, repetida com ênfase pelo usuário):** precisa ser **profissional e elegante**, nunca com "cara de SaaS" nem mecânico. Fluidez é palavra-chave. Especificamente pediu:
- Animações nas transições entre seções/páginas.
- Animações em imagens.
- Efeitos 3D.
- Bordas e estados de hover animados.

**Como aplicar:** antes de montar qualquer tela deste site, rodar o checklist de [[reference_may_memory_vault]] (`26-DESIGNER/DIRETRIZES-UX-UI.md`) e usar isso como direção visual — o padrão de UI do painel administrativo (Tailwind utilitário, paleta `#FF441F`, cards retos) é o app; este site institucional é deliberadamente um projeto visual à parte, mais experiencial/editorial, não deve herdar a cara do painel. Ainda não há protótipo, wireframe nem rota criada — é briefing puro, aguardando o usuário liberar o início (estava no meio de testar a feature de adicionais quando pediu pra guardar isso).
